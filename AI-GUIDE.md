## Что за сайт

- Портфолио mila harys — стилист, арт-директор, модель. Домен **milaharys.com**.
- Статичный сайт: HTML + CSS + JavaScript, без фреймворков, без сервера, без базы данных.
- Код в GitHub-репозитории **milaharys/me** (ветка `main`).
- Хостинг — **Спринтхост** (не GitHub Pages). Правка в GitHub на сайт сама **не попадает** — её надо залить в Спринтхост (см. «Публикация»).

## Структура репозитория

```
docs/                   ← САМ САЙТ. Ровно это лежит на хостинге в public_html
  index.html            страница; <title> и мета-теги превью ссылок между <!-- meta:start --> и <!-- meta:end -->
  assets/style.css      весь дизайн: цвета, шрифт, размеры, отступы, анимации
  assets/js/            логика (ES-модули, подключаются с ?v=<версия>)
    boot.js             старт
    main.js             главный экран, переключение разделов
    router.js           адреса: '' (главная), #/model, #/styling, #/gallery, #/gallery/<съёмка>, #/archive, #/look/<id>, #/contact
    strip.js            лента кадров на главной
    wardrobe.js         разделы gallery и archive (сетка съёмок)
    credit.js           «powered by» с логотипом XTC внизу gallery
    viewer.js           полноэкранный просмотр кадра
    media.js            загрузка фото/видео
    markup.js           HTML-разметка интерфейса
  data/manifest.json    СГЕНЕРИРОВАН: список съёмок и кадров + копия content/site.json
  data/version.txt      СГЕНЕРИРОВАН: версия кода (сброс кеша у посетителей)
  media/{rail,full,poster,small}/   СГЕНЕРИРОВАНЫ: сжатые фото (webp) и видео (mp4)
  favicon.ico, favicon.png, apple-touch-icon.png, og.jpg   СГЕНЕРИРОВАНЫ из логотипа
content/
  site.json             имя, роль (текст превью ссылок и вкладки), почта, instagram, telegram, подписи разделов
  meta.json             по каждой съёмке: title, year, credits, link, order, railCount; по кадру: caption, hide
  brand/logo.svg        логотип → фавикон, иконка iPhone, картинка превью ссылок
tools/build-media.mjs   сборщик (npm run media)
media-src/              исходники фото — ТОЛЬКО на компьютере Милы, в GitHub их нет
```

Дизайн-токены в начале `docs/assets/style.css` (`:root`): `--paper` фон, `--ink` текст, `--muted` серый, `--sans` шрифт, `--gutter` поля. Весь текст на сайте в нижнем регистре (`text-transform:lowercase` у body).

## Сборщик: `npm run media`

Требует Node.js; один раз `npm ci` в папке репозитория.

- **Есть `media-src/`** (компьютер Милы): режет фото и видео в `docs/media/`, пишет `docs/data/manifest.json`, дописывает новые съёмки в `content/meta.json`, обновляет мета-теги в `docs/index.html`, иконки, версию.
- **Нет `media-src/`** (облако, чужой компьютер): фото не трогает; пересобирает иконки из `content/brand/logo.svg`, переносит `content/site.json` в манифест и мета-теги, обновляет версию.

Запускать после любых правок `content/`, `docs/assets/` или логотипа. Если запустить нельзя (ChatGPT), правь `docs/index.html` и `docs/data/manifest.json` напрямую, а Миле скажи, что после заливки нужно обновить страницу с Cmd+Shift+R.

### Как устроены фото (`media-src/`)

```
media-src/<категория>/<съёмка>/<файлы>
```
- Категории: `modeling`, `styling`, `artdir + styling` (подписи и роли — в `content/site.json` → `categories`, `roles`).
- Категория **`archive`** (`media-src/archive/<съёмка>/`) — съёмки только во вкладке archive: их нет ни на главной, ни в gallery. Ссылка archive в меню появляется сама, когда в архиве есть хоть одна съёмка.
- Год в конце имени папки датирует съёмку: `Nasty 24`, `Nasty '24`, `Nasty (2024)`.
- `_текст_` в имени папки → «текст» в кавычках в названии.
- **`!`** в имени файла — кадр попадает на главную ленту. `!` на папке съёмки — вся съёмка на главной (если внутри нет файлов со своим `!`).
- Фото + .mov с одинаковым именем (Live Photo) = один движущийся кадр.
- Скрыть кадр: `"hide": true` у него в `content/meta.json`. Порядок съёмок: `order`. Сколько кадров съёмки в ленте: `railCount`.

## Частые задачи → что править

| Хочу | Где |
|---|---|
| Текст превью ссылок / заголовок вкладки | `content/site.json` → `role` → `npm run media` (или руками 6 мест в `docs/index.html` между meta-комментариями) |
| Почта, instagram, telegram | `content/site.json` → `npm run media` (или `site` в `docs/data/manifest.json`) |
| Название / год / кредиты / ссылка съёмки | `content/meta.json` → `npm run media` (или та же съёмка в `docs/data/manifest.json` → `projects`) |
| Цвета, шрифт, размеры, отступы | `docs/assets/style.css` |
| Поведение (лента, просмотр, меню) | нужный файл в `docs/assets/js/` |
| Логотип / фавикон | заменить `content/brand/logo.svg` → `npm run media` |
| Добавить или убрать фото | только на компьютере Милы: `media-src/` → `npm run media` |
| Отправить съёмку в archive | перенести её папку в `media-src/archive/` → `npm run media` |

## Правила

- Не трогай руками сгенерированное (`docs/media/`, иконки, `version.txt`), если можно запустить сборщик.
- Пути в коде относительные (`assets/…`, `data/…`) — не делай их абсолютными (`/assets/…`).
- Не добавляй фреймворки, сборщики, CDN-библиотеки и трекеры без прямой просьбы.
- Меняешь JS или CSS без `npm run media` — у посетителей может остаться старая версия из кеша; скажи об этом Миле.
- В конце ответа всегда напиши **список изменённых файлов внутри `docs/`** — это то, что Мила зальёт на хостинг.

## Публикация (объясни Миле этими шагами)

1. Сохранить правку на GitHub: файл → ✏️ → вставить → **Commit changes** (или Claude Code пушит в `main` сам).
2. Спринтхост → **Файлы** → `domains/milaharys.com/public_html/`. Там то же, что в `docs/`: `index.html`, `assets/`, `data/`, `media/`, иконки, `og.jpg`.
3. **Мало файлов:** зайти в ту же папку, что в `docs/` (например `assets/js`), кнопка загрузки ⬆ → выбрать файл → заменит старый.
4. **Много файлов / новые фото:** GitHub → **Code → Download ZIP** → распаковать → в `me-main/docs/` нажать **Cmd+Shift+.** (показать скрытые файлы — нужен `.htaccess`) → выделить всё → **Сжать** → в `public_html` выделить всё и удалить → загрузить zip → **Распаковать** → удалить zip и `__MACOSX`.
5. Проверить milaharys.com с **Cmd+Shift+R**.

## Если что-то сломалось

- **Сайт без оформления, просто синие ссылки** — файлы лежат не в корне `public_html` (например в `public_html/docs/`). Вырезать содержимое `docs` → вставить в `public_html` → удалить пустую `docs`.
- **Изменения не видны** — Cmd+Shift+R или режим инкогнито; проверить, что файл реально заменился (дата изменения в файловом менеджере Спринтхоста).
- **Старый фавикон** — браузер держит его в кеше; проверить в инкогнито.
- **Старое превью ссылки в Telegram** — отправить `milaharys.com` боту @WebpageBot.
- **Сайт пустой после правки JS** — ошибка в коде: откатить файл на GitHub (History → предыдущая версия) и залить её заново.
